# AI 真心话扭蛋

## 这是什么

一个**方向实验**，不是产品。

要验证的问题只有一句：

> **能不能让一个完全不懂技术的用户，用他手机上已经在聊天的那个 AI，三十秒内玩到一个真正在玩着的游戏 —— 而不用装 MCP、不用注册、不用 API key、不用服务器？**

## 原理：把游戏规则放进网页

规则不在客户端里，在**网页**里。

用户点一下旋钮，复制出去的是「来抽一题真心话 + 链接」。粘贴给他平时聊天的 AI。
那个 AI 用它**自带的网页访问能力**打开链接，页面里埋着的指令告诉它接下来干什么：
选一个编号 → 拼出结果页地址 → 打开它 → 读到题目 → 回答。

于是整条链路里：

- **没有 MCP、没有插件、没有 API key** —— AI 只要「能读网页」就够，而这是几乎所有主流聊天 App 的默认能力
- **没有注册、没有数据库、没有后端** —— 整个站是纯静态文件
- **没有账号、没有付费墙** —— 27 道题直接写死在 HTML 里

技术上只做了两件事：

**1. 把交互协议降级成「读网页」。**
常规做法是给 AI 装工具（写个 MCP、接个 API），用户要先配置才能玩。这里反过来：
AI 点开一个普通网页，网页自己把游戏规则念给它听。摩擦从「配置」降成「复制粘贴」。

**2. 把同一段指令埋进多个 AI 能读到的地方。**
不同 App、不同模型抓网页的方式不一样 —— 有的只读 `<meta>`，有的读 HTML 注释，
有的取 DOM 文本，有的只认 `<html data-ai-task>`。所以指令埋在四层，
外加 `ai.txt` / `llms.txt` / `robots.txt` 两个纯文本入口，任何一种抓法都读得到。
漏掉哪一层，校验器会报出是哪层。

还有一条同样重要，是实测踩出来的：

**3. 别让 AI 把网页当任务做。**
拿到陌生链接，AI 的默认反应是「把这个网页分析一遍」——复述文案、点评结构，然后什么也没抽到。
所以页面最前面写死了「这是一个游戏，不是一个任务」。

## 给谁玩

**已经在用 AI 陪聊的人，但只是轻度使用。**

不是给会折腾的人：不需要自建服务器、写 API、配 MCP、跑 node。
打开手机 App，复制一句话，发给 AI —— 这就是全部操作。

具体画像：拿豆包 / DeepSeek / ChatGPT 当树洞或陪伴聊，但不玩本地模型、不调 API、不折腾框架的人。

## 玩法

1. 打开初始页，拧一下旋钮 —— 剪贴板里出现「来抽一题真心话 + 链接」
2. 粘给陪你聊天的 AI（**它会自己开局**，你不用多说）
3. 它自己抽一道题、当场回答你

题库只有一套（`q01`–`q27`），抽到就自己答；答完要不要把话头交回给你，由 AI 自己决定。

## 题库

`questions.json` 是唯一需要手工维护的文件（`id` 从 `q01` 起连续编号）。
改完跑 `node tools/build.js` 重新生成。

某道题如果是应季的（比如万圣节），给它加一个 `season` 字段：

```json
{ "id": "q26", "season": "halloween", "text": "……" }
```

标记之后，这道题在**结果页角标、给 AI 的指令、隐藏题库表格、纯文本镜像、index.json**
里都会带上同一个标签 —— 人和 AI 看到的是同一个说法。
过季之后把 `season` 字段删掉，这道题就变回常驻题，**编号不变**。

节日登记表在 `tools/seasons.js`，新增节日往那儿加一条：

```js
halloween: {
  label: "万圣节限定",
  en: "HALLOWEEN",
  window: { from: "10-24", to: "11-01" }   // 节日期间
}
```

`window` 是节日期间。**在这个区间内，AI 会先问用户一句「今天有万圣节限定题，要不要抽一道？」**，
用户说要就抽限定题，说不要就正常随机抽常驻题 —— 整段对话最多问这一次。

页面替不了 AI 判断「今天是几号」，所以指令里给的是**日期区间**，
由 AI 用它自己知道的当前日期去比；它要是没法确认当前日期，就当没有这回事，直接随机抽题。

## 更新记录

主页最下方有一段折叠的「更新记录」，内容来自仓库根目录的 `CHANGELOG.md`。

写法很简单：`## 2026-10-28` 开头一条，下面用 `- ` 写这次改了什么，新的写在最上面。
改完跑一次 `node tools/build.js`，主页上就更新了（只显示最近 5 条）。

这段是给人看的，指令里也明说了：AI 不要复述它、不要拿它当提问素材。

写题目的判据（针对陪伴型聊天场景逐条踩出来的）：

1. **不能有预设答案** —— 拿掉选项后答案还剩多少区分度？
2. **答完必须产出一样具体的东西** —— 一个刻度、一个名字、三个意象、一句话、一份清单。
   只能再输出一段画像分析的题，不要。
3. **不能要求 AI 知道它无从知道的事** —— 它只有聊天记录，没有你的线下数据。
4. **必须留一个「猜」的口子** —— 问句预设了它知道，它就只能编。
5. **不能尴尬、不能冷场** —— 读完人要想答。
6. **不能让 AI 交一份「框架」** —— 学术定义、判定算法这类输出读完什么也没剩下。
7. **要贴近日常** —— 一条消息、一顿饭、一次汇报，比哲学题好接。

## 跑起来

```bash
node tools/build.js --base http://localhost:5173   # 生成
node tools/check.js                                # 校验结构与指令埋点
node tools/verify-consistency.js                  # 核对表格/结果页/txt/题库四者一致
node tools/serve.js                                # http://localhost:5173/
```

正式验证必须用公网 HTTPS 地址 —— AI 访问不了 `localhost`。

## 部署

纯静态，GitHub Pages / Netlify / Vercel / 任意对象存储都行。
初始页里写给 AI 的地址来自构建时的 `--base`，**部署前务必用真实域名重新生成一次**。

```
node tools/build.js --base https://<真实域名>
```

## 合规

主域名备案号 `沪ICP备2026016090号-1` 静态挂在每个页面底部，
链接到 `beian.miit.gov.cn`（工信部要求，不挂是罚款项）。
子域名共用主域备案，不需要单独备案。

页面上的外部域名走白名单校验：多一个就报错。
理由是这个站是给 AI 读的 —— 冒出来一个陌生域名，AI 可能把它当成「这个网站的权威地址」。
